# Разбор задания MLsysd

Проверена ветка `detector-remaster`, исходный коммит `9c45ee2`.
Автор проекта: Абрамов Никита.

## Что требует задание

В PDF два задания. Первое — выбрать и описать проект. Второе — оформить
обучение и предсказание в устанавливаемый Python-пакет.
Проект даёт 30% итоговой оценки, устный экзамен — 60%, тесты по теории — 10%.
Границы оценок: 85%, 70%, 55%.

В тексте указан учебный семестр «осень 2025», срок выбора темы — 15 октября,
срок сдачи работы — за два дня до экзамена. Даты экзамена в файле нет.

Для получения оценки должны выполняться все необходимые условия:

1. Репозиторий открыт и доступен по переданной преподавателю ссылке.
2. Сдаваемый код находится в `main` или `master`. Другие ветки не проверяются.
3. Тема соответствует описанию из первого задания.
4. Все разделы со звёздочкой реализованы хотя бы в базовом виде.

Проверяющий клонирует репозиторий, создаёт чистое окружение, устанавливает
зависимости, выполняет `pre-commit install`, `pre-commit run -a`,
запускает обучение и предсказание. Поэтому наличие файлов недостаточно:
команды должны работать последовательно на новом компьютере.

### Данные и обработка

Взяты фотографии Market-1501 и разметка Market-1501 Attribute.
Код проекта не копируется из репозитория разметки: скачивается только `.mat`.
Загрузки закреплены версиями и SHA256.

Исходное разбиение содержит 751 человека для обучения и 750 для теста.
Из обучающих людей 20% выделяется в validation. Разделение воспроизводимо,
seed задаётся конфигом. Кадры одного человека не пересекают границы частей.
Из тестовой части исключены фоновые и неразмеченные ID.

Разметка объединяется в 12 категориальных атрибутов: пол, возрастная группа,
длина волос, длина рукавов, длина и тип нижней одежды, головной убор,
рюкзак, сумка, дамская сумка и два цвета одежды. Цветовые бинарные столбцы
переводятся в один номер класса. Если цвет не указан, используется `-100`:
такие метки не участвуют в loss, accuracy и F1.

Вход модели — кроп человека. Изображение переводится в RGB, меняет размер
до 128×64 и нормализуется. Случайное отражение применяется только при обучении.
Размер, нормализация и вероятность отражения вынесены в Hydra.

### Модель и обучение

Один ResNet18 извлекает признаки. Линейный слой выдаёт логиты 12 атрибутов.
Это проще и легче девяти независимых ResNet50. По умолчанию предобученный
backbone заморожен, обучается только классификатор. BatchNorm в замороженной
части также остаётся в режиме eval. Можно включить обучение всей сети
параметром `model.freeze_backbone=false`.

Функция ошибки — среднее CrossEntropy по атрибутам с известными метками.
Оптимизатор AdamW. Lightning выполняет обучение, validation, clipping,
выбор устройства и сохранение лучшего checkpoint по validation macro F1.
Accuracy считается по всем известным меткам, macro F1 — по классам внутри
каждого атрибута, затем усредняется по атрибутам.

### Хранение

Git хранит код, конфиги, DVC-указатели и учебные графики с логами.
Фотографии, разметка, checkpoint, ONNX и TensorRT engine в Git не попадают.
Локальное хранилище DVC находится в `.dvc-storage`, кеш — в `.dvc/cache`.
На новом компьютере `download_data()` восстанавливает локальное хранилище
из открытых URL. Свой checkpoint нужно передать отдельно с DVC-хранилищем
или получить повторным обучением.

## Дополнительные баллы

Эти разделы не помечены звёздочкой.

| Критерий                | Баллы по PDF | Реализация                                                          |
| ----------------------- | ------------ | ------------------------------------------------------------------- |
| ONNX                    | 5            | `had export`, проверка совпадения с PyTorch для batch 1 и 2         |
| TensorRT                | 5            | `had tensorrt`, вызов NVIDIA `trtexec`; нужен TensorRT и NVIDIA GPU |
| MLflow Serving          | До 5         | `had package`, стандартный сервер MLflow, клиент запроса            |
| Triton Inference Server | До 10        | `had triton`, model repository с ONNX, конфиг и HTTP-клиент         |

В PDF написано «Trion», по контексту имеется в виду NVIDIA Triton.
Два сервера предлагаются как альтернативы, складывать их баллы не следует.
ONNX-конвертация обработки изображений здесь не нужна: обработка тривиальна.
TensorRT экспортируется без калибровочных данных, поэтому отдельный
калибровочный набор в DVC не требуется.

## Проверка объёма изменений

Добавлены инструменты, прямо названные в задании, реальный датасет вместо
утерянного и небольшая модель для обучения. Существующий видеопайплайн
сохранён. Добавлен backend `market`, использующий новый checkpoint.

Схемы Market-1501 и старых весов различаются. В командном предсказании
возвращаются все 12 исходных атрибутов Market-1501. В старом видео API
сохраняются девять ключей. Возраст и тип верхней одежды остаются
«не определен»: точных соответствий в разметке нет. При наличии головного
убора его тип также не определяется.

Новые боты, интерфейсы, базы данных приложения и облачная инфраструктура
не добавлялись. Docker видеоприложения и прежняя установка MiniCPM
оставлены отдельным дополнительным путём.

## Перед сдачей

1. Использовать шаблон преподавателя для итогового PDF описания.
2. Перенести проверенный коммит в `main` или `master` и отправить в GitHub.
3. Переименовать GitHub-репозиторий в `human-attributes-detector`.
4. Проверить открытый доступ по ссылке, переданной преподавателю.
5. Передать веса через DVC-хранилище либо выполнить обучение по README.
6. Подготовиться объяснить обработку разметки, разделение людей,
   замороженный ResNet18, CrossEntropy, accuracy, F1 и выбор checkpoint.

Согласование темы, уникальность среди групп и дату экзамена определяет
преподаватель. Изменение кода эти вопросы не решает.
