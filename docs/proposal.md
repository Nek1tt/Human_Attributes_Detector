# Human Attributes Detector: распознавание внешних атрибутов людей на видео

Никита Абрамов

## Постановка задачи

Система обнаруживает людей на видео, отслеживает их между кадрами и определяет внешние атрибуты: пол, возрастную группу, одежду и сумки. Результат используется как структурированное описание людей в видеозаписи. Код и команды запуска находятся в [репозитории проекта](https://github.com/Nek1tt/Human_Attributes_Detector).

### Формат входных и выходных данных

На вход видеосервиса подаётся видеофайл. На выходе получаются MP4 с рамками и подписями и JSONL с временем, track_id, координатами, уверенностью детектора и девятью полями атрибутов. Классификатор также работает отдельно с RGB-кропом человека и возвращает 12 атрибутов Market-1501. При переносе в старую схему API возраст и тип верхней одежды остаются «не определен»: классы датасета не совпадают с прежними категориями.

### Метрики

При обучении записываются CrossEntropy, accuracy и macro F1. Ошибка усредняется по атрибутам, macro F1 — по классам каждого атрибута, затем по атрибутам. Неизвестные метки цвета исключаются из расчёта. Метрики, гиперпараметры и Git commit сохраняются в [MLflow](https://mlflow.org/docs/latest/), три графика и журнал — в plots. Для скорости измеряются задержка предсказания и потребление видеопамяти.

### Валидация

751 человек исходной обучающей части разделяется на 601 человека для train и 150 для validation. Используется seed 42. Фотографии одного человека находятся только в одной части. Лучшая модель выбирается по validation macro F1. Отдельная тестовая часть содержит 750 других людей и не используется для выбора checkpoint.

### Данные

Используются [Market-1501](https://zheng-lab-anu.github.io/Project/project_reid.html) и [разметка атрибутов авторов](https://github.com/vana77/Market-1501_Attribute). После исключения неразмеченных ID остаются 10 550 обучающих, 2386 валидационных и 13 115 тестовых изображений. Разметка объединяется в 12 атрибутов: пол, возраст, волосы, рукава, длина и тип нижней одежды, головной убор, рюкзак, сумка, дамская сумка и цвета верха и низа. Изображения и веса хранятся через [DVC](https://dvc.org/doc). Основные сложности — дисбаланс классов, перекрытия людей, освещение и низкое разрешение.

## Моделирование

### Бейзлайн

Бейзлайн — предобученный [ResNet18 из torchvision](https://docs.pytorch.org/vision/stable/models/generated/torchvision.models.resnet18.html) и линейный классификатор атрибутов. Изображение преобразуется в RGB, масштабируется до 128×64 и нормализуется. Обучается последний слой. Модель работает на CPU и CUDA. Старые backends ResNet50 и MiniCPM INT4 сохранены отдельно.

### Основная модель

Основная модель использует визуальный энкодер [MiniCPM-o 2.6](https://huggingface.co/openbmb/MiniCPM-o-2_6) без языковой и аудиочастей. RGB-кроп 224×112 даёт 128 токенов размерности 1152. Они проецируются в 256 признаков и проходят два Transformer-слоя с четырьмя головами внимания. После усреднения токенов линейный слой выдаёт 39 логитов для 12 атрибутов.

Обучение выполняется в [PyTorch Lightning](https://lightning.ai/docs/pytorch/stable/), оптимизатор — AdamW. Сначала пять эпох обучается только Transformer-голова. Затем загружается лучший checkpoint и пять эпох дообучаются голова и два последних блока энкодера. Используются BF16 mixed precision и batch 32. Learning rate на втором этапе: 0.0001 для головы и 0.00001 для энкодера. Размер изображения и параметры обучения задаются в [Hydra](https://hydra.cc/docs/intro/).

Людей обнаруживает YOLO ONNX, сопровождение выполняет [SFSORT](https://github.com/Applied-Deep-Learning-Lab/SFSORT). Атрибуты сохраняются по track_id и повторно используются в следующих кадрах.

## Внедрение

FastAPI-сервис принимает видео, создаёт задачу и позволяет скачать результат. Обе новые модели подключаются через общий backend. Для отдельного предсказания на кропах используется команда had infer; для HTTP-предсказаний — MLflow Serving. Окружение фиксируется в uv.lock. Данные, исходные визуальные веса и обученные checkpoint-файлы хранятся в DVC и не входят в Git. Установка, обучение и самостоятельные проверки описаны в README.
